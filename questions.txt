(1) For the single runs in plot-single.png, execution time increases as the matrix size increases, reaching about 2.57 seconds for the largest run. CPU usage also increases, starting at around 50% and then staying around 92–100% for the larger matrix sizes. In plot-multi.png, where 10 matrix multiplications are running concurrently, each process takes around 3.15–3.30 seconds and uses about 15–16% CPU. This is expected since the processes are sharing the available CPU resources. When multiple multiplications run at the same time, each process gets a smaller share of the CPU, which results in an increase in the time to completion. 

(2) In plot-taskset.png, execution time is relatively consistent across all 10 concurrent processes, at around 3.51–3.55 seconds. In plot-multi.png, the execution times have more variation, from about 3.15–3.30 seconds. CPU usage is also lower and more consistent with taskset, staying around 9% for every process, compared to about 15–16% in plot-multi.png. This is because taskset pins each process to the same CPU core, so all of the processes are restricted instead of being able to run on other CPU cores. The taskset results are more consistent, however, the processes have to share the same CPU core. 

(3) There is more variation between the processes in plot-nice.png compared to plot-multi.png. In plot-multi.png, all 10 concurrent processes have relatively similar execution times and CPU usage, at around 3.15–3.30 seconds and 15–16% CPU. With the different nice values, runs 1–5 with priority 0 finish much faster, around 1.57–1.98 seconds, and have higher CPU usage, around 25–33%. Runs 6–10 with priority 7 take around 3.0–3.2 seconds and use about 14–16% CPU. This shows that the lower nice value allows the processes to get a larger share of the CPU, while the higher nice value processes get less CPU.
